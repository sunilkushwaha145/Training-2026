var vs let vs const

Understanding the differences between variable declaration methods is crucial for modern JavaScript development.

Aspect var let const
Scope Function-scoped Block-scoped Block-scoped
Redeclarable Yes No No
Reassignable Yes Yes No
Hoisting Hoisted (undefined) Hoisted (TDZ) Hoisted (TDZ)
Modern Standard Outdated Recommended Recommended
Definition: var

var is the original variable declaration keyword. It has function scope and can be redeclared.

var name = "Suryansh";
console.log(name); // John
var name = "Suryansh"; // Redeclared
console.log(name); // Jane
Output: Suryansh
Output: Suryansh
Explanation: var allows redeclaration. The second var name declaration doesn't cause an error and overwrites the first value. This flexibility can lead to bugs.
Definition: let

let is block-scoped and prevents redeclaration but allows reassignment. It's the modern standard.

let age = 25;
console.log(age); // 25
age = 26; // Reassigned (allowed)
console.log(age); // 26
let age = 27; // Error: Identifier 'age' has already been declared
Output: 25
Output: 26
Error: Redeclaration not allowed
Explanation: let prevents accidental redeclaration (safer) but you can update the value through assignment. This is the preferred way to declare variables in modern JavaScript.
📝 Definition: const

const is block-scoped, prevents redeclaration AND reassignment. Use by default unless you need to change the value.

const PI = 3.14159;
console.log(PI); // 3.14159
PI = 3.14; // Error: Assignment to constant variable
const PI = 3.1; // Error: Identifier 'PI' has already been declared
Output: 3.14159
Error: Cannot reassign
Error: Cannot redeclare
Explanation: const creates immutable variables. Once assigned, the value cannot change. This is best for values that should remain constant throughout your program.
Block Scope Example
function demo() {
var x = 1;
let y = 2;
const z = 3;

{
var x = 10; // Updates outer x
let y = 20; // New y in this block
const z = 30; // New z in this block
}

console.log(x); // 10 (var is function-scoped)
console.log(y); // 2 (let is block-scoped)
console.log(z); // 3 (const is block-scoped)
}
Output: 10
Output: 2
Output: 3
Explanation: var is function-scoped, so the inner var x = 10 updates the outer x. let and const are block-scoped, so the inner y and z are separate from the outer ones.

== vs ===

Equality operators are fundamental. Understanding the difference prevents subtle bugs in your code.

Aspect == (Loose Equality) === (Strict Equality)
Type Coercion Yes (converts types) No (no conversion)
Comparison Value only Value AND type
Example 5 == "5" → true 5 === "5" → false
Safety Unpredictable Predictable
Best Practice Avoid Always use
Definition: ==

Loose equality compares values after type conversion. Different types are converted to match.

console.log(5 == "5"); // true (5 converted from string)
console.log(0 == false); // true (false converts to 0)
console.log("" == false); // true (both are falsy)
console.log(null == undefined); // true (special case)
console.log(1 == true); // true (true converts to 1)
Output: true
Output: true
Output: true
Output: true
Output: true
Explanation: Loose equality performs type coercion. JavaScript converts types to make the comparison. This can lead to unexpected results, which is why === is preferred.
Definition: ===

Strict equality compares both value and type. No type conversion happens.

console.log(5 === "5"); // false (different types)
console.log(0 === false); // false (different types)
console.log("" === false); // false (different types)
console.log(null === undefined); // false (different types)
console.log(1 === true); // false (different types)
console.log(5 === 5); // true (same value and type)
Output: false
Output: false
Output: false
Output: false
Output: false
Output: true
Explanation: Strict equality requires both value AND type to match. 5 and "5" are not equal because one is a number and the other is a string. This is safer and more predictable.
Real-World Example
let userAge = "25";
let minAge = 18;

// Dangerous with ==
if (userAge == minAge) {
console.log("Comparing with ==: Condition is true");
// This executes because "25" is converted to 25
}

// Safe with ===
if (userAge === minAge) {
console.log("Comparing with ===: Condition is true");
// This doesn't execute because "25" (string) is not 25 (number)
} else {
console.log("Types don't match - use proper type conversion");
}
Explanation: == caused unexpected behavior by converting string to number. === caught the type mismatch. Best practice: Always use === to avoid bugs.

++a vs a++

Pre-increment and post-increment both increase values but at different times. The difference matters in expressions.

Aspect ++a (Pre-increment) a++ (Post-increment)
Increment Timing BEFORE returning value AFTER returning value
Value Returned New value (incremented) Old value (before increment)
Performance Slightly faster Creates temporary copy
Example Effect let b = ++a; // a then b = incremented value let b = a++; // a = incremented, b = old value
Definition: ++a (Pre-increment)

Increments the variable first then returns the new value for use in expressions.

let a = 5;
let result = ++a; // a increments to 6, then returns 6
console.log("a: " + a); // 6
console.log("result: " + result); // 6
Output: a: 6
Output: result: 6
Explanation: ++a increments a to 6 FIRST then returns 6 to result. Both variables end up with the value 6.
Definition: a++ (Post-increment)

Returns the current value first then increments the variable for the next use.

let a = 5;
let result = a++; // returns 5 then a increments to 6
console.log("a: " + a); // 6
console.log("result: " + result); // 5
Output: a: 6
Output: result: 5
Explanation: a++ returns the original value 5 to result THEN increments a to 6. This is why result gets 5 while a becomes 6.
Complex Expression Example
let x = 5;
let y = 10;
let result1 = ++x + y; // x becomes 6 then 6 + 10 = 16
console.log("Using ++x: " + result1); // 16

let a = 5;
let b = 10;
let result2 = a++ + b; // 5 + 10 = 15 then a becomes 6
console.log("Using a++: " + result2); // 15
Output: Using ++x: 16
Output: Using a++: 15
Explanation: In expressions, ++x increments first (6) then adds, while a++ adds the old value (5) then increments. The difference affects the result.

--a vs a--

Pre-decrement and post-decrement work the same way as their increment counterparts but in the opposite direction.

Aspect --a (Pre-decrement) a-- (Post-decrement)
Decrement Timing BEFORE returning value AFTER returning value
Value Returned New value (decremented) Old value (before decrement)
Example Effect let b = --a; // a then b = decremented value let b = a--; // a = decremented, b = old value
Definition: --a (Pre-decrement)

Decrements the variable first then returns the new value for use in expressions.

let a = 10;
let result = --a; // a decrements to 9 then returns 9
console.log("a: " + a); // 9
console.log("result: " + result); // 9
Output: a: 9
Output: result: 9
Explanation: --a decrements a to 9 FIRST then returns 9 to result. Both end up with the value 9.
Definition: a-- (Post-decrement)

Returns the current value first, then decrements the variable for the next use.

let a = 10;
let result = a--; // returns 10 then a decrements to 9
console.log("a: " + a); // 9
console.log("result: " + result); // 10
Output: a: 9
Output: result: 10
Explanation: a-- returns the original value 10 to result THEN decrements a to 9. result preserves the old value while a is decremented.
Countdown Example
// Using pre-decrement
let count1 = 5;
console.log("Pre-decrement:");
console.log(--count1); // 4
console.log(--count1); // 3
console.log(--count1); // 2

// Using post-decrement
let count2 = 5;
console.log("\nPost-decrement:");
console.log(count2--); // 5
console.log(count2--); // 4
console.log(count2--); // 3
Output: Pre-decrement:
Output: 4
Output: 3
Output: 2
Output:
Output: Post-decrement:
Output: 5
Output: 4
Output: 3
Explanation: Pre-decrement (--count) prints decremented value immediately. Post-decrement (count--) prints the old value first. In loops either works but the printed output differs.
